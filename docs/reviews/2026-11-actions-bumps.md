## PR 5: upload-artifact 4.6.2 to 7.0.2

**Verdict: merge as is**, subject to the manual release check below. [PR 5](https://github.com/jakobmart4/Scannx-Tools/pull/5) head `250267cb25e4483e1e474df4e40613478152bf1b` changes only the upload action in `release.yml`. Its [v7.0.2 tag resolves to the pin](https://github.com/actions/upload-artifact/compare/v7.0.2...cf430e030ddbb5b0abf93d22962f4752f3646cd9), `cf430e030ddbb5b0abf93d22962f4752f3646cd9`.

- [v5.0.0](https://github.com/actions/upload-artifact/releases/tag/v5.0.0) marks Node 24 support as a major transition. [v6.0.0](https://github.com/actions/upload-artifact/releases/tag/v6.0.0) changes the default runtime to Node 24 and requires runner 2.327.1 or later. [v7.0.0](https://github.com/actions/upload-artifact/releases/tag/v7.0.0) switches to ESM and adds optional unarchived single-file uploads. With `archive: false`, multiple files fail and `name` is ignored. [v7.0.1](https://github.com/actions/upload-artifact/releases/tag/v7.0.1) updates documentation and dependencies; [v7.0.2](https://github.com/actions/upload-artifact/releases/tag/v7.0.2) updates retry handling and the artifact library.
- `release.yml` supplies `name: scannx-zip`, `path: dist/` and `if-no-files-found: error`. The [v7.0.2 manifest](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/action.yml) retains these inputs and defaults `archive` to true, so the single-file restriction and name change do not apply. No step consumes artifact outputs. This is a GitHub-hosted `windows-latest` job, not a pinned self-hosted runner; confirm its actual runner version meets the Node 24 requirement in the run log. Its `contents: write` permission is already available; no new explicit repository permission is specified by this upload input. The workflow artifact is distinct from the files that `gh release create` publishes.
- After merge, the separately authorized manual release run must pass tests and build, upload an artifact named `scannx-zip`, and contain both the expected `Scannx-vX.Y.Z.zip` and `.sha256`. Compare the checksum to the zip and inspect its entries. A manual dispatch must not create a GitHub release or attestation.

## PR 6: attest-build-provenance 3.2.0 to 4.2.2

**Verdict: merge as is**, with tag-triggered attestation explicitly unverified. [PR 6](https://github.com/jakobmart4/Scannx-Tools/pull/6) head `6e3f9ded19ea1fee8db59a1a498fd9bb8e73960e` changes only the attestation action in `release.yml`. Its [v4.2.2 tag resolves to the pin](https://github.com/actions/attest-build-provenance/compare/v4.2.2...4d101475d8b20a2381f78447822ac1eab6504dd8), `4d101475d8b20a2381f78447822ac1eab6504dd8`.

- [v4.0.0](https://github.com/actions/attest-build-provenance/releases/tag/v4.0.0) replaces the implementation with a composite wrapper around `actions/attest`; the existing action remains supported. [v4.1.0](https://github.com/actions/attest-build-provenance/releases/tag/v4.1.0), [v4.1.1](https://github.com/actions/attest-build-provenance/releases/tag/v4.1.1), and [v4.2.2](https://github.com/actions/attest-build-provenance/releases/tag/v4.2.2) update the wrapped action, with later support for a subject version and storage records. The [pinned wrapper manifest](https://github.com/actions/attest-build-provenance/blob/4d101475d8b20a2381f78447822ac1eab6504dd8/action.yml) pins its inner `actions/attest` to the full commit `508db95dd578ae2727ebd6217d5ba78e4fbda05d` and forwards `subject-path`; the [inner manifest](https://github.com/actions/attest/blob/508db95dd578ae2727ebd6217d5ba78e4fbda05d/action.yml) uses Node 24. Runner 2.327.1 or later is needed for Node 24; verify the hosted runner log.
- The job has `id-token: write` and `attestations: write`, plus `contents: write`, and supplies only `subject-path: dist/*.zip`. No outputs are consumed. The [inner action's general permissions guidance](https://github.com/actions/attest/blob/508db95dd578ae2727ebd6217d5ba78e4fbda05d/README.md) also lists `artifact-metadata: write` for storage records. The [implementation](https://github.com/actions/attest/blob/508db95dd578ae2727ebd6217d5ba78e4fbda05d/src/attest.ts) enters storage-record creation only for registry pushes; the wrapper defaults `push-to-registry` to false. Thus this ZIP invocation does not take that path, and adding the extra permission is not indicated by static inspection. The action defaults to build provenance when no SBOM or custom predicate is supplied.
- A manual dispatch after merge can demonstrate that checkout, tests, build and artifact upload succeed and that tag-only attestation and publication are skipped. It **cannot** validate the new attestation action. At a separately authorized tag-triggered release, check that the attestation step succeeds, the expected zip is the subject, the release assets are present, and `gh attestation verify <zip> --repo <owner>/<repo>` succeeds. No tag or release is requested by this review.

## PR 7: checkout 4.4.0 to 7.0.1

**Verdict: merge as is**, subject to the manual release check below. [PR 7](https://github.com/jakobmart4/Scannx-Tools/pull/7) head `e2db6f3502798fea77f181ee9240696158dede5f` changes checkout in both workflows. Its [v7.0.1 tag resolves to the pin](https://github.com/actions/checkout/compare/v7.0.1...3d3c42e5aac5ba805825da76410c181273ba90b1), `3d3c42e5aac5ba805825da76410c181273ba90b1`.

- [v5.0.0](https://github.com/actions/checkout/releases/tag/v5.0.0) moves to Node 24 and requires runner 2.327.1 or later. [v6.0.0](https://github.com/actions/checkout/releases/tag/v6.0.0) moves persisted credentials into a separate runner-temporary file. The [v7 README](https://github.com/actions/checkout/blob/3d3c42e5aac5ba805825da76410c181273ba90b1/README.md) notes runner 2.329.0 or later for authenticated Git commands in Docker container actions; neither workflow uses such a container action and both set `persist-credentials: false`. [v7.0.0](https://github.com/actions/checkout/releases/tag/v7.0.0) rejects unsafe fork PR checkout for `pull_request_target` and `workflow_run` by default and switches to ESM. These workflows use `pull_request`, tag push and `workflow_dispatch`, not those privileged triggers. [v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1) adjusts the unsafe check, branch whitespace and argument escaping.
- Both workflows retain `contents: read` at workflow scope; the release job explicitly receives `contents: write`. Checkout has its existing input and no consumed outputs. The [PR CI run](https://github.com/jakobmart4/Scannx-Tools/actions/runs/43492985669) succeeded for the reviewed head and exercises checkout in `ci.yml`; it does not exercise `release.yml`. It predates current main, so recheck after the PR is updated or merged.
- After merge, the separately authorized manual release run must check out the intended ref, validate the selected version's notes, pass tests, build and upload `scannx-zip`, with no release or attestation on dispatch. Verify the hosted runner version and the expected files as in PR 5.
