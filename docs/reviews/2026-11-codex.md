# Independent review of changes after v1.0.0

Reviewed base: `29df0e07b3abe2e1aa852f8f1df9f1ab2c5cfb23`.

## Findings

### Major: unusable PresentMon file blocks FrameView

`disk-log.ps1:38-38,59-65` | Confidence: checked by tracing.

Input: a run folder contains a valid `FrameView_game.exe_2026_11_10T100010_Log.csv` and an empty or header-only `frames.csv`. Existence alone selects PresentMon; no frames enter `$by`, and the valid FrameView file is never read. The report has no frame statistics despite the promised fallback when there are no PresentMon frame times.

Minimal fix: parse PresentMon first and fall back when it yields no usable frames. Test empty and header-only files.

### Major: unrelated captures compete globally

`disk-log.ps1:36-38,51-52,75,379` | Confidence: checked by tracing.

Input: an Apex run has a 1,000-frame `FrameView_r5apex.exe_2026_11_10T100010_Log.csv` with swap chain `0x1` and a 2,000-frame `FrameView_other.exe_2026_11_10T100010_Log.csv` with `0x2`. Both are copied and parsed; `$best` chooses `0x2`, so the verdict and F9 diagnosis use another application's frames. If processes reuse the same address, their rows are mixed instead.

Minimal fix: select captures belonging to the requested game and identify chains by process and capture as well as address; combine sequential captures deliberately. Test multiple applications and reused addresses.

### Major: failed final write can delete the complete report

`scan-check.ps1:48-52` | Confidence: checked with an isolated fault injection in Windows PowerShell 5.1.

Input: `Out-File` creates a nonempty output and then throws while writing, for example when the disk fills after the header. The catch discards the failure; a recent nonempty output satisfies line 51. `Finish` deletes the complete `.partial` and prints `Done` for an incomplete report.

A scratch test loaded `Finish` from the script and replaced `Out-File` with a function that wrote `header only` and then threw. `Finish` returned `Done`, deleted `.partial`, and left only `header only` in the output. This simulates the failure path; it is not a real disk-full test.

Minimal fix: track whether the entire write succeeded and remove `.partial` only after successful completion. Test a write that fails after creating a nonempty output.

### Major: traversal failures are silently reported as complete

`scan-check.ps1:164-184` | Confidence: checked by tracing.

Input: a popped directory throws access denied during file or directory enumeration, attribute retrieval, or enumeration of a pruned directory. The empty catch discards the error and the directory has already been popped. If the remaining stack finishes, the report claims zero unvisited folders and does not add `COULD NOT READ`, despite the missed subtree.

Minimal fix: record failed directories in `$unread`, including partial enumeration failures, and distinguish failed from budget-unvisited folders. Test a synthetic enumeration failure.

### Major: trusted directory exempts arbitrary task executables

`scan-check.ps1:24,29-31,39-40` | Confidence: checked by tracing.

Input: `TaskOdd '\' 'Updater' 'C:\ProgramData\Microsoft\Windows Defender\evil.exe' ''` returns nothing before checking the unusual ProgramData path, even though the executable is not Defender. The same folder exemption applies to services. An unexpected file in that tree bypasses the rule.

Minimal fix: constrain the exemption to expected Defender executables and validate publisher or surface unknown executables. Add negative task and service examples.

### Minor: quoted FrameView fields shift columns

`disk-log.ps1:45-50` | Confidence: checked by tracing, conditional on such a field occurring in a capture.

Input: with header `Application,TimeInSeconds,MsBetweenPresents` and row `"Game, Deluxe",10,50`, splitting at every comma makes the time field ` Deluxe"`, so the valid frame is silently skipped. A later comma can shift sensor data.

Minimal fix: parse CSV quoting and add quoted commas and escaped quotes to synthetic tests. Check a real FrameView capture for actual occurrence.

### Minor: miner task names under Microsoft are not checked

`scan-check.ps1:34-35` | Confidence: checked by tracing.

Input: `TaskOdd '\Microsoft\Windows\Foo\' 'Windows System Health' 'C:\Windows\System32\cmd.exe' ''` returns nothing. The `elseif` prevents the miner-name check for tasks under Microsoft even when the executable passes the path check.

Minimal fix: check the name independently after the Microsoft path test, with an explicit exception for any established legitimate task.

### Minor: ProgramData substring flags ordinary filenames

`scan-check.ps1:16,32,40` | Confidence: checked by tracing.

Input: `TaskOdd '\' 'Updater' 'C:\Program Files\Vendor\ProgramDataHelper.exe' ''` reports an unusual place because `ProgramData` is an unanchored substring. `SvcOdd 'D:\Games\ProgramDataHelper.exe'` similarly flags an ordinary folder.

Minimal fix: match the actual ProgramData path component with boundaries and test a filename containing that text.

## Coverage and boundaries

- `TaskOdd`: tests cover a ProgramData script-host argument and an ordinary Program Files application with a ProgramData data argument. An encoded PowerShell command does not expose its decoded path to the regex. The Microsoft-name and Defender-directory exceptions are findings above.
- `SvcOdd`: tests cover Windows Temp, a ProgramData lookalike name, system/Defender paths and an ordinary game folder. The Defender-directory exemption and substring collision are findings above. Services outside the named unusual places are listed but not flagged by this rule.
- `BadExclusions`: tests cover executable extensions, a drive root and Temp, plus a normal game folder. An exclusion such as `D:\Games\ordinary.exe` does not match the suspicious patterns; the caller still reports the existence of non-matching exclusions. This is a heuristic, not a complete risk classification.
- `ThreatNames`: tests cover known, unknown and duplicate IDs, and an empty list. A failed name lookup leaves IDs unknown, but detections still get a flag via the fallback.
- `$trusted`: tests cover Google and developer application directories and reject vendor names embedded elsewhere. Files placed under `AppData\Local\Programs\` are excluded from the new-executables list regardless of publisher; known marker names are checked before that exclusion. `$prune` checks immediate marker names in a pruned directory, but a marker nested under `node_modules\subdir` is not visited. These are breadth and traversal tradeoffs, not proof of a clean tree.
- `TryRead`: tests check success, a missing path and the expected no-events error. It records only the last of multiple errors, and a terminating exception escapes rather than being recorded. Not every scan read uses it. `Finish`: success and an output directory in the way are tested; the injected partial-write case above is not.
- Ordinary-PC examples were checked as rule inputs, not against an inventory of real machines: tests cover Program Files paths, Discord cache and `node_modules` pruning; Discord and Steam roots and `AppData\Local\Programs` are excluded from the new-executable list. VPN, Tailscale, OEM and anti-cheat installations were not empirically sampled, so no false-positive rate is claimed.
- FrameView: existing tests exercise `NA` sensor cells and one capture's timestamp alignment. Quoted fields, unrelated captures and empty PresentMon files are findings above. Sequential captures with different swap-chain addresses compete for one winner. Midnight wrapping appears at `disk-log.ps1:55` and sorting at lines 84-89; cross-midnight verdicts are already a known issue in `docs/NEXT.md`. Actual capture filename time semantics remain unverified.
- Test review: the positive and negative tests named above assert observable outputs. I did not identify a specific assertion that necessarily passes with its rule deleted. Mutation testing was not performed, so this is not a claim that all tests can fail.
## Not verified

- No real scan or real FrameView capture was run. Filename start-time semantics, actual quoting and real multi-process capture behavior remain unverified.
- No real disk-full or access-denied fault was induced; the partial-write path was simulated and the traversal finding follows the code. No mutation testing or full Pester suite was run.
- The targeted Windows PowerShell 5.1 Pester 3.4 scan-rule and FrameView suites were run with process-local execution-policy bypass; see PR evidence for the final result.

## Looked at and found fine

- Synthetic FrameView tests exercise explicit source selection, PresentMon precedence when it has frames, NA sensor values, one capture's clock alignment, and missing capture timestamps.
- `ThreatNames` retains an unknown ID, `N` filters nulls before counting, and `BadExclusions` handles the tested executable extensions. These checks do not establish comprehensive malware coverage.
- The regional-format change sets invariant culture before serialization and parsing; existing tests cover representative decimal-comma and dot-separated-time cases. Midnight verdict handling is already listed in `docs/NEXT.md`.
